## ADDITIONAL ISSUES FOUND

### Issue A: RUNTIME BUG --- handle-condition crashes (HIGH IMPACT)

**File:** `agent-class.lisp:354`
**Code:**
```lisp
(funcall (agent-restart-policy) condition agent)
```
**Problem:** `agent-restart-policy` is an accessor (slot reader). When called with
zero arguments `(agent-restart-policy)`, CLOS signals a `NO-APPLICABLE-METHOD` error
because the reader requires an `agent` instance. This means every call to
`handle-condition` will **crash at runtime**.

**Fix:**
```lisp
(funcall (agent-restart-policy agent) condition agent)
```

### Issue B: API Incompatibility --- list-agents and inspect-agent shadowing (MEDIUM IMPACT)

Two functions are defined in both `orchestrator.lisp` and `dashboard.lisp` with
**incompatible signatures**:

| Function | orchestrator.lisp | dashboard.lisp |
|----------|-------------------|----------------|
| `list-agents` | `(list-agents &optional orchestrator)` returns alist | `(list-agents)` no args, returns list of triples |
| `inspect-agent` | `(inspect-agent agent-id &optional orchestrator)` | `(inspect-agent agent-id)` no orchestrator arg |

Since `dashboard.lisp` is compiled after `orchestrator.lisp` (serial order), the
dashboard versions shadow the orchestrator versions. Code that calls
`(list-agents some-orch)` will fail after dashboard is loaded.

**Fix options:**
1. Rename dashboard versions to `print-agent-list` and `show-agent-details`
2. Make dashboard versions accept the same optional arguments
3. Remove orchestrator.lisp versions (they're superseded by dashboard)

### Issue C: DEFGENERIC for notify-* missing method combination caveat

The `:around` methods on `(setf agent-health)` and `(setf agent-status)`
(agent-class.lisp:309-332) call `notify-health-change` and `notify-status-change`
after `call-next-method`. These generic functions are defined with `DEFGENERIC`
but no explicit method combination. The `:after` methods in `orchestrator.lisp`
and `dashboard.lisp` rely on standard method combination. This is correct but
worth noting for maintainers.

### Issue D: Example code in comments references undefined functions

The commented example block in `conditions.lisp` (lines 434-506, inside `#|...|#`)
references functions not defined anywhere:
